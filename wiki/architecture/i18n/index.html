Multilingual sites

A site serves several languages by declaring an i18n block in app.json. Without the block the site is monolingual and nothing in the build changes (same URLs, same dist/).

Configuration

"i18n": {
  "defaultLocale": "it",
  "prefixDefaultLocale": true,
  "locales": {
    "it": { "lang": "it-IT", "label": "Italiano" },
    "en": { "lang": "en-US", "label": "English", "labels": { "skipLink": "Skip to the content" } }
  }
}
Key Notes
defaultLocale Must be one of the locales keys; the build stops otherwise
prefixDefaultLocale true (default): every language lives under its code (/it/, /en/). false: the default language has no prefix
locales.<code> The code is the URL segment. Only letters, digits, - and _
locales.<code>.lang BCP 47 tag: <html lang>, hreflang, og:locale, dates, numbers and prices
locales.<code>.label Name shown in the LanguageSwitcher
locales.<code>.labels Same shape as the root labels; overrides it for that language

Walle passes defaultLocale, the codes and prefixDefaultLocale to Astro’s own i18n routing (with redirectToDefaultLocale: false, so / stays the site’s: a page or astro.redirects) and the code → lang map to @astrojs/sitemap, which writes xhtml:link hreflang alternates.

Pages and content

Walle does not prescribe routes. A site puts its pages under src/pages/<code>/ or a dynamic src/pages/[lang]/; Astro.currentLocale is then the code. Content collections hold one folder per language with the same path in each (posts/it/a.md, posts/en/a.md): the entry id is <code>/<path> and entries with the same <path> are translations of each other.

A page that has no translation does not exist in that language: the site simply does not generate it, and the helpers below leave it out.

What walle provides

API Use
label(path, override, code), labeler(code) Interface strings for a language: prop override, then locales.<code>.labels, then root labels, then the English default. Every walle component calls labeler(Astro.currentLocale)
locale(code) The language’s BCP 47 tag, for formatters. Without a code, website.language
localizedUrl(code, path) URL of a site path (no language, no base) in a language, honoring prefixDefaultLocale, trailingSlash and the base path
stripLocale(pathname) { code, path } of a request pathname, or null outside every language
getTranslations(collection, id) Codes in which the entry exists, drafts excluded. Import from @walle/utils/translations (it reads astro:content, so it is not in the @walle/utils barrel)
headerTranslations (layouts) Codes in which the page exists: two or more emit <link rel="alternate" hreflang> (plus x-default for the default language)
LanguageSwitcher <LanguageSwitcher translations={codes} />: links to the same page in the other languages, only those listed; nothing with fewer than two. Label labels.language.nav

<html lang> is the language’s lang unless the layout gets headerLanguage.

Limits

  • The sitemap derives each page’s alternates by swapping the language segment of the URL, so a translation with a different slug gets no sitemap alternate (the page’s own hreflang links are still correct).
  • navbar.json and footer.json are one file for all languages. A site that needs per-language navigation overrides the components (see components).
  • Missing translations are not served in the default language: the page does not exist.
  • Domains per language need server rendering and are not supported.
